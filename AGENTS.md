# Formula 1 Atlas — правила работы агентов

Используйте субагентов только для независимых, чётко ограниченных частей задачи. Для небольшой очевидной правки работайте одним агентом.

## Рекомендуемая маршрутизация

- Перед изменением сложного или незнакомого потока данных используйте `code_mapper`
- Для визуальной ошибки сначала используйте `browser_debugger`, затем `ui_fixer`
- Для существенной переработки экрана используйте `ui_designer`, затем `frontend_developer`
- Для трасс, конфигураций, сезонов, GeoJSON и туристических данных используйте `data_engineer`
- Для схемы, миграций и пространственных запросов используйте `postgres_pro`
- Для истории Formula 1, эволюции трасс, пилотов, команд и временных шкал используйте `f1_history_researcher`
- Для отбора туристических объектов, районов размещения и сценариев маршрутов используйте `travel_curator`
- Для поиска медиаматериалов, проверки лицензий и ведения реестра прав используйте `media_rights_specialist`
- После существенного изменения используйте `reviewer`

## Координация

- Не запускайте параллельно двух агентов с записью в одни и те же файлы
- Предпочитайте параллельность для чтения, исследования, диагностики и проверки
- Основной агент сохраняет за собой требования пользователя, окончательные решения и сводный ответ
- Перед редактированием проверяйте рабочее дерево и сохраняйте несвязанные изменения пользователя
- Не создавайте коммит без прямого запроса пользователя

## Особенности продукта

- Интерфейс и редакционные подписи должны быть на русском языке
- В одиночных текстовых блоках и строках не ставьте лишнюю точку в конце; в тексте из нескольких предложений сохраняйте нормальную пунктуацию
- Не выдумывайте геометрию трасс, исторические данные, результаты, координаты, авторство или права на изображения
- Разделяйте трассу, место проведения, конфигурацию, этап и сезон как разные сущности
- В картографических изменениях проверяйте камеру, источники, слои, 3D-рельеф, очистку ресурсов и мобильное отображение
