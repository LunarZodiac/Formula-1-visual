# Конвейер данных Formula 1

## Цель

Один и тот же процесс должен уметь первоначально заполнить сезоны с 1950 года,
а затем обновлять только изменившиеся данные текущего сезона. Браузер не
обращается к спортивным API напрямую: это защищает интерфейс от лимитов,
изменений ответа и временной недоступности источника.

## Поток данных

```text
Jolpica / проверенные геоданные / редакторские материалы
                         ↓
                  raw (без правок)
                         ↓
       нормализация идентификаторов и валидация
                         ↓
                PostgreSQL + PostGIS
                         ↓
          JSON / GeoJSON / векторные тайлы
                         ↓
                    веб-приложение
```

## Первоначальное заполнение 1950–2026

1. Скачать версионированную выгрузку Jolpica и сохранить сведения об источнике.
2. Загрузить сезоны, участников, этапы, сессии и результаты во временные таблицы.
3. Сопоставить внешние идентификаторы с устойчивыми идентификаторами атласа.
4. Добавить геометрию трасс и связать этап с правильной исторической
   конфигурацией.
5. Выполнить проверки полноты и только после этого обновить основные таблицы.
6. Сформировать снимки JSON, которые читает текущий интерфейс.

Импорт должен быть повторяемым: повторный запуск обновляет записи, а не создаёт
дубликаты. Для каждого запуска фиксируются источник и время получения.

## Обновление активного сезона

Во время сезона обновление выполняется по расписанию на сервере или в GitHub
Actions:

- редко — календарь, трассы, команды и составы;
- после каждой сессии — классификация и быстрые круги;
- после этапа — положения в личном и командном зачётах;
- вручную после проверки — факты, фотографии и редакторские тексты.

Если API недоступен или проверка не пройдена, опубликованный снимок не
заменяется. Поэтому сайт продолжает показывать последнюю корректную версию.

## Пространственные данные

Геометрии трасс, POI и здания проходят отдельную проверку системы координат,
точности и лицензии. Массовая 3D-застройка экспортируется по тайлам и уровням
масштаба. Детальные модели не включаются в общий набор зданий и загружаются
только по запросу пользователя.

## Ближайшая реализация

Первый импортёр будет работать с одним сезоном в режиме предварительного
просмотра, формировать отчёт об ошибках и ничего не записывать без успешной
валидации. После проверки на сезонах 1950, 2024 и 2026 его можно будет запустить
для всего диапазона.

Предварительная проверка уже доступна и не требует пароля от PostgreSQL:

```powershell
node scripts/jolpica-preview.mjs --season 2024
```

Скрипт соблюдает пагинацию API, делает запросы последовательно и повторяет
только временные ошибки (`429` и `5xx`). Он не создаёт и не изменяет файлы.
